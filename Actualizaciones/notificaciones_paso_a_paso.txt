# Flujo de Notificaciones en Datus (Aplicación Cliente) y ADMIN-EXPO-DATUS (Aplicación Administrador)

Este documento detalla el proceso de cómo se manejan las notificaciones entre la aplicación de administración (ADMIN-EXPO-DATUS) y la aplicación cliente (Datus).

## 1. Creación/Gestión de Notificaciones (ADMIN-EXPO-DATUS)

*   **Ubicación:** `ADMIN-EXPO-DATUS/services/notificacionesService.js`
*   **Descripción:** Esta aplicación es utilizada por los administradores para crear, obtener, actualizar y eliminar notificaciones.
*   **Funcionamiento:**
    *   Se conecta a la base de datos de Supabase.
    *   Interactúa con la tabla `notificaciones` para realizar operaciones CRUD (Crear, Leer, Actualizar, Eliminar).
    *   Cada notificación creada incluye un `title` (título), `details` (detalles/cuerpo del mensaje), y opcionalmente un `url` (enlace asociado). También se registra automáticamente la fecha y hora de creación (`created_at`).

## 2. Registro de Dispositivo para Notificaciones Push (Datus - Aplicación Cliente)

*   **Ubicación:** `Datus/services/notificationService.js`
*   **Descripción:** Este servicio es fundamental para que la aplicación cliente pueda recibir notificaciones push.
*   **Funcionamiento:**
    *   La función `registerForPushNotificationsAsync()` se encarga de este proceso.
    *   **Solicitud de Permisos:** Primero, solicita al usuario los permisos necesarios para enviar notificaciones push al dispositivo.
    *   **Obtención del Token:** Si los permisos son concedidos, la función obtiene un `expo_push_token` único para el dispositivo actual. Este token es esencial para que el servicio de notificaciones de Expo sepa a qué dispositivo enviar el mensaje.
    *   **Guardado del Token:** El `expo_push_token` obtenido se guarda en la tabla `profiles` de Supabase, asociado al `id` del usuario que ha iniciado sesión. Esto permite que las notificaciones futuras puedan ser dirigidas específicamente a este dispositivo.

## 3. Envío de Notificaciones Push (Backend/Supabase - Proceso Implícito)

*   **Ubicación:** No directamente en el código proporcionado (se asume un proceso de backend).
*   **Descripción:** Este paso es el puente entre la creación de la notificación por el administrador y su recepción en el dispositivo del cliente.
*   **Funcionamiento (Asumido):**
    *   Se espera que exista un mecanismo de backend (posiblemente una función de Supabase, un webhook o un servicio externo) que monitoree la tabla `notificaciones` en Supabase.
    *   Cuando se detecta una nueva notificación o una actualización relevante, este servicio:
        *   Recupera los `expo_push_token` de los usuarios a los que se debe enviar la notificación (obtenidos de la tabla `profiles`).
        *   Utiliza estos tokens para enviar la notificación a través del servicio de notificaciones push de Expo.

## 4. Recepción y Visualización de Notificaciones (Datus - Aplicación Cliente)

*   **Ubicación:** `Datus/app/src/main/java/datus/app/com/ui/screens/NotificationsScreen.kt`
*   **Descripción:** Esta es la pantalla de la aplicación cliente donde los usuarios pueden ver y gestionar sus notificaciones.
*   **Funcionamiento:**
    *   **Carga de Notificaciones:** La pantalla obtiene la lista de notificaciones de un `themeViewModel` (que a su vez las carga desde Supabase o un caché local).
    *   **Agrupación y Visualización:** Las notificaciones se agrupan por fecha de creación y se muestran en una lista desplazable (`LazyColumn`). Cada notificación se presenta en una `Card` individual.
    *   **Contenido de la Notificación:** Cada tarjeta muestra el `title` y `details` de la notificación.
    *   **Interacción con URL:** Si una notificación incluye un `url`, al hacer clic en la tarjeta, la aplicación intenta abrir ese enlace en el navegador web predeterminado del dispositivo.
    *   **Marcado como Leída:** Al hacer clic en una notificación, la aplicación llama a `themeViewModel.markNotificationAsRead(notification.id)` para marcarla como leída. Esto probablemente actualiza el estado de la notificación en la base de datos o en el almacenamiento local para que no aparezca como "nueva" la próxima vez.

## Posibles Problemas y Puntos de Verificación en la Aplicación Cliente (Datus):

Si la aplicación cliente está experimentando problemas con las notificaciones, se recomienda revisar los siguientes puntos:

1.  **Permisos de Notificación:**
    *   Asegurarse de que la aplicación esté solicitando correctamente los permisos de notificación al usuario.
    *   Verificar que el usuario haya concedido estos permisos en la configuración del dispositivo.

2.  **Registro y Guardado del Token:**
    *   Confirmar que la función `registerForPushNotificationsAsync()` se esté ejecutando correctamente.
    *   Verificar en la base de datos de Supabase (tabla `profiles`) que el `expo_push_token` se esté guardando correctamente para cada usuario. Un token incorrecto o ausente impedirá la recepción de notificaciones.

3.  **Conectividad a Supabase:**
    *   Asegurarse de que la aplicación `Datus` tenga una conexión a internet estable y pueda comunicarse con Supabase para cargar las notificaciones y actualizar su estado.

4.  **Lógica de Backend/Envío de Notificaciones:**
    *   Aunque fuera del código de la aplicación, es crucial verificar que el servicio de backend (el que envía las notificaciones push a través de Expo) esté funcionando correctamente y se esté activando cuando se crean nuevas notificaciones.

5.  **Manejo de Notificaciones en Segundo Plano/Cerrada:**
    *   Investigar cómo la aplicación maneja las notificaciones cuando no está activa (en segundo plano o completamente cerrada). Expo tiene configuraciones específicas para esto que deben ser implementadas correctamente.

6.  **Sincronización de la Interfaz de Usuario:**
    *   Asegurarse de que la `NotificationsScreen.kt` se actualice dinámicamente cuando llegan nuevas notificaciones o cuando se marca una como leída, para reflejar el estado más reciente.
